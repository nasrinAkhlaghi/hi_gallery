# اجرای محلی و تست HI Gallery در ویندوز

مرحله فعلی: احراز هویت، ثبت‌نام و تأیید فروشنده، مدیریت محصول و آپلود تصویر محلی.
نمایش واقعی محصولات به خریدار، سبد خرید، پرداخت و سفارش هنوز در دست توسعه هستند.

## ۱. پیش‌نیاز و تنظیمات

Python نسخه 3.12 یا بالاتر، Node.js و npm، و Docker Desktop نصب باشند. ابتدا Docker Desktop را باز کنید و منتظر آماده‌شدن Engine بمانید.

PowerShell را در ریشه پروژه باز کنید:

```powershell
cd C:\Users\nasri\PycharmProjects\hi_gallery
```

فایل `.env` فعلی را نگه دارید. فقط اگر این فایل وجود ندارد، آن را بسازید:

```powershell
if (!(Test-Path .env)) { Copy-Item .env.example .env }
```

مقادیر اتصال دیتابیس باید با `POSTGRES_DB`، `POSTGRES_USER`، `POSTGRES_PASSWORD` و `POSTGRES_PORT` هماهنگ باشند. برای لوکال، `ENVIRONMENT=development` باشد. اگر `JWT_SIGNING_KEY` و `CSRF_SIGNING_KEY` خالی هستند، این دستور دو کلید مستقل تولید می‌کند؛ خروجی را در همان کلیدهای `.env` قرار دهید:

```powershell
python -c "import secrets; print('JWT_SIGNING_KEY=' + secrets.token_urlsafe(48)); print('CSRF_SIGNING_KEY=' + secrets.token_urlsafe(48))"
```

برای جلوگیری از ناسازگاری کوکی‌ها، آدرس‌های زیر را یکسان با `localhost` استفاده کنید:

```dotenv
VITE_API_BASE_URL=http://localhost:8000/api/v1
CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
```

محیط مجازی موجود در ریشه پروژه قابل استفاده است. اگر وجود ندارد:

```powershell
python -m venv .venv
```

## ۲. دیتابیس و بک‌اند

در ترمینال اول، از ریشه پروژه:

```powershell
docker compose up -d postgres
docker compose ps
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd backend
..\.venv\Scripts\python.exe -m alembic upgrade head
..\.venv\Scripts\python.exe -m app.seed_dev --admin-email local-admin@example.com
..\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

دستور seed رمز حساب ادمین محلی را از شما می‌پرسد؛ رمز باید ۱۲ تا ۱۲۸ کاراکتر باشد و هنگام تایپ نمایش داده نمی‌شود. این دستور چهار دسته‌بندی نمونه نیز اضافه می‌کند. اجرای دوباره، رمز حساب موجود را تغییر نمی‌دهد و حساب عادی موجود را به ادمین تبدیل نمی‌کند. اگر ادمین از قبل ساخته‌اید، ایمیل دیگری برای این حساب محلی انتخاب کنید. دستور فقط در حالت development اجرا می‌شود و در هر دیتابیسی که `DATABASE_URL` به آن اشاره می‌کند می‌نویسد؛ فقط دیتابیس توسعه محلی را هدف بگیرید.

بررسی بک‌اند:

- سلامت سرویس: <http://localhost:8000/health>؛ انتظار `{"status":"ok"}`.
- مستندات API: <http://localhost:8000/docs>.

نیازی به migration تازه برای محصولات نیست؛ جدول‌های محصول، تصویر و دسته‌بندی از قبل در migration اولیه وجود دارند. اجرای `upgrade head` دیتابیس را تا نسخه `0004_shop_settings` به‌روز می‌کند.

## ۳. فرانت‌اند

در ترمینال دوم:

```powershell
cd C:\Users\nasri\PycharmProjects\hi_gallery\frontend
npm install
npm run dev -- --host localhost --port 5173 --strictPort
```

برنامه را در <http://localhost:5173> باز کنید. هر دو ترمینال بک‌اند و فرانت‌اند باید باز بمانند.

## ۴. تست دستی مسیر کامل

۱. به <http://localhost:5173/register/seller> بروید؛ با ایمیل جدید و رمز حداقل ۱۲ کاراکتری ثبت‌نام کنید.

۲. وارد حساب فروشنده شوید، پروفایل فروشگاه را ذخیره و درخواست بررسی را ارسال کنید. وضعیت باید از پیش‌نویس به در حال بررسی تغییر کند؛ پیش از تأیید، مدیریت محصول در دسترس نیست.

۳. در یک پنجره ناشناس مرورگر، <http://localhost:5173/login> را باز کنید و با `local-admin@example.com` و رمزی که هنگام seed تعیین کردید وارد شوید. به <http://localhost:5173/admin/sellers> بروید، فروشنده را پیدا و تأیید کنید. استفاده از پنجره ناشناس باعث می‌شود کوکی‌های دو حساب جدا بمانند.

۴. در پنجره فروشنده، صفحه را تازه‌سازی کنید. به <http://localhost:5173/seller/products> بروید و «افزودن محصول» را انتخاب کنید.

۵. نام، توضیح، دسته‌بندی، قیمت مثل `125.50` و موجودی مثل `3` را وارد کنید. پیش‌نویس را ذخیره کنید؛ صفحه ویرایش باز می‌شود و آپلود تصویر فعال خواهد شد. قیمت را با ارقام لاتین و نقطه اعشار وارد کنید. واحد پول هنوز در قرارداد محصول تعیین نشده؛ فعلاً نماد ارزی نمایش داده نمی‌شود.

۶. یک JPEG، PNG یا WebP غیرمتحرک تا ۵ مگابایت و ۱۶ میلیون پیکسل آپلود کنید. تصویر باید نمایش داده شود و پس از تازه‌سازی باقی بماند. فایل‌ها در `backend/uploads/products` ذخیره می‌شوند و آدرس‌های رسانه در API از `/media/products/` شروع می‌شوند. می‌توانید مسیر ذخیره را با `PRODUCT_UPLOAD_DIR` تغییر دهید. تصویر اول جلد است و ترتیب تصاویر همان ترتیب آپلود است.

۷. قیمت/موجودی را ویرایش کنید، وضعیت را روی «منتشرشده» بگذارید و ذخیره کنید. به فهرست بازگردید و فیلتر وضعیت را تست کنید. انتشار در این مرحله وضعیت محصول را تغییر می‌دهد؛ صفحه نمایش عمومی محصولات هنوز ساخته نشده است.

۸. حذف تصویر و حذف محصول را امتحان کنید؛ هر دو تأیید صریح می‌خواهند. برای محصول استفاده‌شده در سبد، سفارش یا نظر، حذف با خطای 409 رد می‌شود؛ می‌توانید وضعیت را غیرفعال کنید.

۹. زبان را به فارسی تغییر دهید و فرم، فهرست و پیام‌ها را بررسی کنید. با یک فروشنده تأییدشده دیگر، آدرس ویرایش محصول فروشنده اول باید «پیدا نشد» برگرداند.

آپلود محلی برای توسعه است؛ در حالت production پاسخ 503 می‌دهد تا پیش از اتصال فضای ذخیره مناسب، فایل روی دیسک موقت سرور ذخیره نشود. آدرس فایل‌های محصول عمومی است؛ فایل خصوصی آپلود نکنید. فایل‌های روی دیسک و دیتابیس باید با هم نگهداری و پشتیبان‌گیری شوند.

## ۵. بررسی تنظیمات فروشگاه

پس از تأیید فروشنده و اجرای migration `0004_shop_settings`، مسیر <http://localhost:5173/seller/shop> را باز کنید:

۱. نام، توضیحات، نشانی لوگو و دسته‌بندی اصلی را تغییر دهید. دسته‌بندی فروشگاه مستقل از دسته‌بندی هر محصول است و می‌تواند خالی بماند.

۲. تم‌های گالری، کتان و سفال را با کلیک یا کلیدهای صفحه‌کلید انتخاب کنید. پیش‌نمایش باید بلافاصله تغییر کند؛ تا پیش از ذخیره هیچ درخواستی برای تغییر فروشگاه ارسال نمی‌شود. «کنار گذاشتن تغییرات» باید فرم و تم را به آخرین حالت ذخیره‌شده برگرداند.

۳. ذخیره کنید و صفحه را تازه‌سازی کنید؛ مقادیر ذخیره‌شده باید باقی بمانند. پاک‌کردن لوگو، توضیحات یا دسته‌بندی هم مجاز است. در صورت خطای ذخیره، متن واردشده باید حفظ شود.

۴. با «مدیریت محصولات» و «افزودن محصول» به فرم‌های موجود بروید. «مشاهده فروشگاه» صفحه عمومی واقعی را با تم ذخیره‌شده و محصولات منتشرشده باز می‌کند.

۵. زبان فارسی و انگلیسی، چیدمان موبایل، ترتیب فوکوس، حالت‌های بارگذاری و خطا را بررسی کنید. فروشنده تأییدنشده باید به صفحه وضعیت درخواست هدایت شود.

## ۶. بررسی صفحات خریدار

۱. بدون ورود یا در پنجره ناشناس، `/browse` و `/categories` را باز کنید. از صفحه اصلی هم لینک جست‌وجو و کارت دسته‌بندی باید به این صفحات برسد.

۲. نام محصول را جست‌وجو کنید، دسته‌بندی انتخاب کنید و صفحه را تغییر دهید. جست‌وجو، دسته‌بندی و شماره صفحه باید در URL باقی بمانند؛ تغییر فیلتر باید صفحه‌بندی را از ابتدا شروع کند. بازکردن لینک کپی‌شده و دکمه‌های عقب/جلو مرورگر باید همان فیلترها را بازگرداند.

۳. جزئیات یک محصول را باز کنید؛ تصویر اصلی و تصاویر دیگر، قیمت، نام فروشنده، دسته‌بندی و موجودی را بررسی کنید. محصول ناموجود یا با موجودی صفر باید ناموجود نمایش داده شود. دکمه خرید فعال در این مرحله وجود ندارد.

۴. روی نام فروشنده بزنید؛ صفحه `/shops/:sellerId` باید نام، لوگو یا جایگزین، توضیحات، دسته‌بندی اصلی و تم ذخیره‌شده فروشگاه را نشان دهد. فیلتر دسته‌بندی محصولات داخل فروشگاه مستقل از دسته‌بندی اصلی آن است.

۵. محصول DRAFT یا INACTIVE و فروشگاه تأییدنشده نباید با URL مستقیم قابل مشاهده باشد. فروشگاه بدون محصول باید پیام مناسب داشته باشد. تصویر خراب، خطای شبکه، تلاش مجدد و صفحه خالی را هم بررسی کنید.

۶. چیدمان دسکتاپ و موبایل، فارسی/راست‌به‌چپ و انگلیسی، دسترسی با صفحه‌کلید و خوانایی هر سه تم را بررسی کنید. تکمیل این بررسی بصری و جریان کامل فروشنده تا خریدار، مرحله ۵ برنامه است.

## ۷. تست خودکار

ترمینال جداگانه، از ریشه پروژه:

```powershell
cd backend
..\.venv\Scripts\python.exe -m pytest -q
cd ..\frontend
npm test
npm run build
```

تست‌های معمول بک‌اند دیتابیس SQLite موقت دارند و از PostgreSQL توسعه استفاده نمی‌کنند. تست‌های یکپارچه اختیاری PostgreSQL فقط با تنظیم `TEST_DATABASE_URL` برای یک دیتابیس مجزا و دورریختنی و `TEST_DATABASE_ISOLATED=1` اجرا می‌شوند. هرگز آدرس دیتابیس اصلی را به تست یکپارچه ندهید.

اگر محیط sandbox ساخت پوشه موقت pytest را مسدود کرد، یک پوشه موقت مخصوص همان اجرا داخل پروژه با `--basetemp=.pytest_cache/local-run-1` تعیین کنید. این مسیر مخصوص خروجی تست باشد، چون pytest محتوای آن را پاک می‌کند.

## رفع اشکال

- خطای `docker_engine` یا `dockerDesktopLinuxEngine`: Docker Desktop اجرا نشده یا Engine هنوز آماده نیست.
- خطای اتصال دیتابیس: `docker compose ps` و پورت/نام کاربری/رمز در `.env` را بررسی کنید.
- خطای کلید امضا: دو کلید `.env` خالی نباشند و هرکدام حداقل ۳۲ بایت باشند.
- خطای ورود یا CSRF: همه صفحات را با `localhost` باز کنید؛ بین `localhost` و `127.0.0.1` جابه‌جا نشوید. پس از تغییر `.env` سرویس‌ها را دوباره اجرا کنید.
- نبود دسته‌بندی: دستور seed را روی همان دیتابیس توسعه اجرا کنید.
- پورت 5173 اشغال است: سرویس قبلی را متوقف کنید؛ تغییر پورت به تغییر `CORS_ALLOWED_ORIGINS` هم نیاز دارد.
- صفحات عمومی فروشگاه، Browse، دسته‌بندی و جزئیات محصول به API وصل‌اند؛ سبد خرید و سفارش همچنان جای‌نگهدار هستند.
